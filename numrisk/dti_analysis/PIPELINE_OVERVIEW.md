### ⚠️ Note: two independent preprocessing chains

The FA pipeline (§2) and the connectome pipeline (§4) each run their **own**
preprocessing of the same raw diffusion data — they are not built on a shared
preprocessed input:

| | FA pipeline (§2) | Connectome pipeline (§4) |
|---|---|---|
| Tool | FSL | MRtrix3 |
| Steps | merge → `topup` → `applytopup` → BET mask → `dtifit` | denoise → degibbs → bias-correct (`dwibiascorrect ants`) → `eddy` (incl. outlier replacement, slice-to-volume) → masking |
| Motion/outlier correction | none beyond `topup` distortion correction | full `eddy` with motion + outlier correction |

This wasn't a deliberate methodological choice — it's a side effect of using
FSL for the FA stream (per Zoltan's advice, scoped narrowly to that workflow)
and adopting Anna Speckert's MRtrix-based connectome pipeline wholesale for
tractography. No one has reviewed whether the FA stream's lighter
preprocessing (no `eddy` motion/outlier correction) is adequate on its own,
or whether FA and connectome results are even comparable given they're
derived from differently-preprocessed versions of the same scans. **Open
question, not yet resolved.**

## 1. Raw data → BIDS

Code: `dti_data_orga.ipynb`

- Raw PAR/REC files (Philips scanner export) per subject on

- `parrec2nii --bvs` converts to NIfTI + generates `.bval`/`.bvec`.
- Two acquisitions per subject — `as` and `ps` (anterior↔posterior phase

- Known data quirks: sub-39 and sub-64 have non-standard filenames (no

**Status: done for all 66 subjects.**

## 2. Classical FA pipeline (`derivatives/dwi_preproc`)

Code/notes: `overview.md`, `dti_data_orga.ipynb` (cells under "Succesfull FA
image generation"). Advice from Zoltan (MR physician) + FSL docs.

Steps, all via FSL:
1. Merge `as`+`ps` DWI volumes and bvals/bvecs into one 4D file per subject.
2. Merge the b0 (non-diffusion-weighted) volumes from both acquisitions.
3. `topup` on the merged b0s for susceptibility/distortion correction
   (`acqparams.txt` encodes phase-encoding direction + echo time).
4. `applytopup` to the full DWI series.
5. Brain mask: `fslmaths -Tmean` on the corrected mean image, then `bet`
   (settled on `-f 0.4` after visual checks; `-f 0.3` masks also kept per
   subject).
6. `dtifit` → tensor-derived maps (FA, MD, L1–L3, V1–V3, MO, S0, tensor).

Per-subject output in `dwi_preproc/sub-XX/`: corrected DWI, brain masks
(`-f03`/`-f04`), full `dtifit` output set, plus `fa_in_T1`/`fa_in_MNI`
(registration to T1 via `flirt`/`bbr`, then to MNI).

**Status: complete for all 66 subjects.** `meanFA_subXtract.csv` at the
top level suggests a subject-mean FA comparison was already computed.

## 4. Tractography & connectomes (`derivatives/dwi_connectome`)

Pipeline: forked from [`annspe/connectome_pipeline`](https://github.com/annspe/connectome_pipeline)
(Anna Speckert) to [`mrenke/connectome_pipeline`](https://github.com/mrenke/connectome_pipeline)
(commit `9fbbb21`), run on a dedicated sciencecloud instance. Adaptation
notes in `connectome_pipelinde.md`; the adapted scripts that actually
produced these derivatives are `DTI_Pipeline_noStops.py` /
`DTI_Pipeline_noStops_GlasserParcel.py` with `config_dti_allSubs*.json`
in that fork.

Per-subject inputs prepared (`t2/`: T1 + FreeSurfer `aparc+aseg.mgz`;
`dti/`: merged DWI + bvals/bvecs from step 2 above), then pipeline runs:

1. **`processing/dti/`**: denoising → degibbs → bias correction → eddy
   (FSL `eddy`) → brain extraction → masking.
2. **`processing/tractography/two_tissue/`**: two-tissue CSD (changed from
   the pipeline's default three-tissue `SS3T` to `SS2T` — see fix in
   `connectome_pipelinde.md`) → probabilistic tractography (`tracks_10mio.tck`,
   downsampled `tracks_200k.tck` for QC) → SIFT2 filtering
   (`sift2_stats.csv`, `SIFT2_mu.txt`).
3. **`processing/connectome/{AAL3_amended, Glasser, Glasser_hemiUnique}/`**:
   parcellation registered to DWI space, SIFT2-weighted structural
   connectome matrix (`connectome.csv`) + streamline-assignment file per
   atlas.

**Status: complete for all 66 subjects, for all 3 atlases.** (`sub-average/`
exists but is empty — a group-average connectome has not been built yet via
*this* pipeline; group-level analysis happens downstream in §5 instead.)
